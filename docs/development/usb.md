# USB device controller and local control-pipe host

## Scope

`src/usb.c` is an original functional S3C2410A USB-device implementation,
referencing the Samsung manual, chapter 13 (especially EP0_CSR, pages 13-12
and 13-13). It covers indexed endpoint configuration, bounded FIFOs, interrupt
latches and an **EP0 packet-level host adapter**. No other emulator's device
implementation is imported. This is not a complete USB 1.1 timing/protocol model.

The public host calls submit SETUP/OUT packets or consume IN packets. A
successful IN call includes the host's ACK; data toggles, CRC errors, retries
without ACK and electrical wire signaling are not modeled. Other endpoint
configuration can be initialized by firmware, but **Bulk host transactions,
DMA transfer, isochronous operation, suspend/resume and actual computer-device
creation are not implemented**. Descriptor endpoint declarations are not a
Bulk-transfer pass. The browser UI has no virtual-USB controls yet.

## Device state and API

Device registers accept little-endian byte or aligned word access. FIFO word
access transfers one payload byte, not four bytes. Halfword and misaligned
accesses stop explicitly. Function address, power, index, interrupt enable,
W1C pending, frame number, MAXP and endpoint CSRs have separate state. Endpoint
0 supports 8/16-byte packets; the four other FIFOs are bounded to 64 bytes.
Disabled DMA configuration may be recorded; enabling it stops rather than
pretending a transfer completed. Unknown addresses and unsupported modes stop.

`orchard_usb_attach()` starts/ends an explicit host-adapter session. Changing
attachment resets the USB block only; it does not reset CPU, RAM or NOR and is
not a measured physical cable/pull-up behavior. Cold machine reset detaches.
`orchard_usb_bus_reset()` explicitly asserts/releases reset; the caller supplies
elapsed virtual time. `orchard_usb_sof()` supplies an 11-bit frame number. No
host traffic, SOF cadence or attachment is silently generated by ordinary runs.

`orchard_usb_setup()`, `orchard_usb_out()` and `orchard_usb_in()` address EP0.
Results distinguish ACK, NAK, STALL, no addressed device and invalid host
arguments. Wrong address and buffer-pressure cases do not silently consume
packets. Function-address changes become active after the status stage, not
while the SETUP is being processed. A superseding SETUP cancels old staging.

The manual defines SETUP_END when a transfer ends before DATA_END. Shortened
descriptor requests exercise this: after the host consumes its requested bytes,
the guest may have prepared more data. Host status OUT flushes that staging,
sets SETUP_END and interrupts the guest. FIFO access remains invalid until the
guest acknowledges it. Simply rejecting guest prefetch, or waiting indefinitely
for DATA_END, broke the original bootloader's first 8-byte request.

The pure 48-word snapshot reports common registers, active address, control
phase, remaining data, attachment/reset and seven fields per endpoint. Reading
it never consumes FIFO bytes or acknowledges IRQs. Native JSON and WASM expose
the same layout; ordinary ROM probes now use schema v6. The host API is not an
arbitrary memory writer, a network listener, WebUSB, or a host-OS driver.

## Original HP50g recovery session

The pinned original 16 KiB HP50g boot region is preserved byte-for-byte in an
explicit 2 MiB erased backing image. **No operating system is supplied and
this is not a recovered full NOR.** Source/backing hashes remain distinct.

Explicit conditions: attached keyboard; strong D `cc7f:0` and G `1:0`; weak G
`f800:f800`; key 1 raw `(3,5)` pressed at quantum 2,000,000 and released at
2,400,000. The USB adapter is attached before execution. Bus reset is asserted
at 3,000,000 and released 500 quanta later, followed by 20,000 guest quanta.
These quanta do not certify physical USB reset or oscillator timing. No LCD
`+0x68` hypothesis is used by this boot-only session.

The following six requests and their status stages complete on **both native
and production WASM**, with an independent cold replay on each:

| Request | Guest-produced result |
| --- | --- |
| Device descriptor, first 8 bytes at address 0 | `12011001ff000008` |
| Device descriptor, all 18 bytes at address 0 | `12011001ff000008f0032101000101020001` |
| SET_ADDRESS 7, still sent to address 0 | Zero-length status ACK; subsequent requests use address 7 |
| Configuration descriptor, first 9 bytes | `090220000101008019` |
| Configuration descriptor, all 32 bytes | `0902200001010080190904000002ff0000000705810240000007050302400000` |
| SET_CONFIGURATION 1 | Zero-length status ACK |

The guest bytes declare VID `03f0`, PID `0121`, EP0 maximum packet 8, and
64-byte Bulk endpoints IN `81` and OUT `03`. The host does not fabricate these
values from a model name. Final observed state: 3,042,500 quanta, 3,042,453
instructions, 47 guest exceptions, active address 7, idle control phase and no
diagnostic stop or data-fault state. The same session completed with optimized
ASan/UBSan native instrumentation against production WASM and cold replays.

**Remaining counterexample:** a subsequent original-firmware GET_CONFIGURATION
stages a byte and sets DATA_END without setting IN_PKT_RDY in the current model.
The host continues to receive NAK. This control path is not accepted; the model
does not invent an IN-ready transition to hide it. The synthetic guest does
pass configuration readback. Consequently SET_CONFIGURATION's status ACK is
not a claim that every standard control request or firmware transfer works.

```sh
node tools/probe-usb.mjs --bootloader /private/boot-50g.bin \
  --output /new/path/control-session.json
```

The wrapper authenticates the source hash, snapshots bytes once, constructs
only erased backing, compares independent C/JS host orchestration, records
binary hashes/conditions/requests, and refuses existing output files. Each
stage is bounded to 100 retries of 1,000 guest quanta. Reports are private local
evidence, not repository or Pages content.

## ROM-free regression

`tests/usb.c` covers register banks/masks, packet bounds, 8/16-byte EP0 data,
all 128 address values, delayed address activation, status phases, short
requests, SETUP_END, STALL recovery, reset/detach, W1C, IRQ routing and malformed
host/guest accesses. Tests remain active in Release and compile as test-only
WASM. `tests/usb-guest.S` is new original assembly, built temporarily by Clang;
it is not extracted firmware. It returns a deliberately non-HP VID/PID, handles
seven control requests including configuration readback, and returns from 26
guest IRQ entries to WFI. Native/WASM architectural output and cold replays
agree. Generated binaries and test modules are never distributed.
